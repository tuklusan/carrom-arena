# OPERATOR DIRECTIVE — Make Carrom Arena a real, presentable game

The Phase-1 audit is already done. Reality on the ground:

- v1.0 was declared "delivered" but the operator has watched the rendered mode and reports: **pieces move jerkily, there is no real game — just pieces sliding around**. The QA certificate in the tree is aspirational; do not trust it.
- ctest on `build/` returns 5/5 pass — meaning the tests do not exercise the visible failure. That is itself a defect: tests are not proving what they claim.

## GOAL (single, non-negotiable)

Produce a **presentable, playable-looking autonomous Carrom game**:

1. The window opens at a size that fits within a typical 1920×1080 display with room for taskbar/titlebar. If the requested size is bigger, clamp it. The board must be fully visible with margin on all sides. No off-screen HUD.
2. Piece motion must be smooth — no jerky teleport-per-frame artifacts. The render loop should interpolate or run at the physics substep rate; if physics is running at a low Hz and rendering samples the raw state, fix that.
3. Physics settling actually works — pieces come to rest cleanly within a reasonable time (< 5 s per shot in wall time at 1× playback), NOT the 30 s safety timeout the README currently admits to. Retune Coulomb (0.12) and viscous (0.85) coefficients as needed; add a small dead-zone velocity threshold if that is what it takes.
4. A full autonomous match (best-of-3 games) plays to completion in rendered mode without freezing, without pieces getting stuck spinning, without the HUD showing garbage, and with the winner announced on screen at the end.
5. HUD is legible: current player highlighted, both team scores visible, queen status visible, shot count visible. No overlapping text. Fonts scale with window size (or use a fixed readable size that fits the smallest supported window).
6. Add ONE regression test that would have caught the "jerky / no real game" state — e.g. a headless soak that asserts every shot settles in bounded wall-time steps AND that a full match reaches a terminal state without hitting the safety timeout. Wire it into ctest.

## Boundaries

- **All project files stay within `~/SOFTWARE-DEVELOPMENT/carrom/` subtree.** No writes outside.
- Do not chase the three deferred README limitations if they are not on the critical path for the goal above (physics settling IS on the critical path — do fix it; `__DATE__` header and full-soak memory are NOT — defer them).
- Cross-platform work is DEFERRED. Focus only on this Linux box.
- Do not weaken existing tests to make them pass. If a test is wrong, fix the test properly and explain why in the commit.
- No premature "delivery" or "QA certificate" claims. The operator will judge presentability by watching the rendered mode.

## Verification the operator will perform

1. `./scripts/clean_build.sh && ./build/carrom_arena --mode=rendered` — watches a full match, expects smooth motion, legible HUD, a winner announced.
2. `cd build && ctest --output-on-failure` — expects 100% pass including the new regression test.
3. `./build/carrom_arena --mode=capture --seed=42 --frames=600 --capture-dir=captures` — inspects a handful of frames for layout correctness.

Design your loop so a `capture` mode run of ~600 frames covers a full shot cycle (aim → strike → settle → next player), and dump one such capture into `captures/` as part of your own verification before declaring done.
