If your layout_compute() reads GetScreenWidth()/GetScreenHeight() only ONCE at startup (cached into a static/global), or if some constant in the code happens to equal 1280x720 and gets used instead of the live value, then any Xvfb test at exactly that size would PASS even though the layout is not actually reactive to real window size. This is almost certainly what happened — the "R1 Strategy A" fix was verified at sizes that accidentally matched a hardcoded assumption, producing a false positive.

**Before writing any fix, grep your own renderer.c for**:
- Any `static` or file-scope variable caching sw/sh, board_size, or Layout struct that is only set once (e.g., inside an `if (!initialized)` block).
- Any literal `1280`, `720`, `1000`, `600` used in place of a live GetScreenWidth()/GetScreenHeight() call in the per-frame draw path.
- Whether `layout_compute()` (or equivalent) is actually called EVERY FRAME inside the render loop, or only once after InitWindow.
